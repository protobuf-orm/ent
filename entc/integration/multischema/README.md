## Multi-schema support

An entity can name the schema its table lives in, and a client can be told a
different one at runtime. Both are exercised by `multischema_test.go`:

- `ent/schema` says nothing, and `TestMySql` passes the mapping in with
  `ent.AlternateSchema(cfg)`.
- `versioned/schema` declares `entsql.Schema` on each entity, so the mapping is
  written down at codegen and arrives as `versioned.DefaultSchemaConfig`.
  `TestSchemaConfigFromAnnotations` runs the same assertions through it.

Both build their databases with ent's own DDL (`schema.Dump`), so the tests
need nothing but the MySQL server the rest of this module uses.

### On the Atlas CLI

This directory used to hold a migration directory applied by `atlas migrate
apply`, generated by:

```shell
atlas migrate diff --to ent://versioned/schema --dev-url docker://mysql/8
```

That command cannot work here. The CLI's `ent://` provider shells out to
`entgo.io/ent/cmd/ent`, and this module is `github.com/protobuf-orm/ent`, so
the CLI cannot read these schemas at all. The directory was therefore
unregenerable and had gone stale against the singular table names -- silently,
because the test that applied it skipped everywhere it ran.

Versioned migration without a CLI is `dialect/sql/schema/versioned.go`:
`Migrations` plans and applies, `Revisions` records what ran, and `Current` and
`Check` refuse a database the code has moved past.
